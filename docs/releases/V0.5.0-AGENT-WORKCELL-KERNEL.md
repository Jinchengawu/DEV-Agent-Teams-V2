# v0.5.0 Agent Workcell Kernel 交付说明

## 版本边界

v0.5.0 将 Agent-Team-OS 从“一个受管代码 Agent 交付到一个 Workspace”扩展为“四个独立
Repository Workcell 组成一个可验证 ReleaseBundle”。它仍是交付控制面，不是多 Agent 聊天界面。

```text
Requirements → Tasking → Plan Gate
  → Design Workcell → Design Gate
  → QA Preparation (Artifact-only)
  → Frontend Workcell ─┐
                         ├→ QA Delivery Workcell
  → Backend Workcell ──┘
  → ReleaseBundleV2 Verification → Release Gate
  → External Forward-only Apply → ReleaseManifestV2
```

Design、Frontend、Backend 和 QA 各有一个 Primary Git Repository。它们不共享 Git Workspace，
跨 Workcell 输入只是内容寻址 Artifact Reference。

## 已实现

- `TeamTemplate` Draft / Validate / Publish / Revision API 及组织拓扑编辑器。
- `ProjectWorkcellBinding` 四仓接入、逐仓能力验证和 Team Activation。
- 不可变 `DeliveryExecutionSnapshot`：冻结 Team、Pipeline、Provider、Workspace 和 Method Pack。
- `WorkcellRun` / `AgentRun` Tree / `AgentAttempt` / `DelegationPlan` / `ReviewArtifact` /
  `WorkcellResult`。
- Main planning → Writer → Machine Verification → 并行 Reviewer → Main synthesis →
  Product Result Validation。
- Child 深度、数量、并发、Writer 唯一性、Wall-clock Budget、取消和重启中断约束。
- 锁定 `bmad-method@6.11.0` 与 `bmad-method-test-architecture-enterprise@1.23.4`；
  Archive/Registry/Content/Qualification 完整性校验和临时只读 Overlay。
- 外部 GitHub HTTPS Candidate Branch、幂等 PR Review Surface、顺序 Forward-only Apply、
  `needs_attention`、`release_drifted` 和同 Bundle `resume-forward`。
- `WorkspaceCandidateV2`、`ReleaseBundleV2`、`RemoteApplyReceipt` 和 `ReleaseManifestV2`。
- 新控制台视图：组织模板、四仓接入、Main/Child/Attempt Tree、Method Hash、PR、
  Apply Receipt 和 Release Drift。
- 迁移 `0030–0035`；不修改 `0001–0029`，保留旧 Journey、V1 Candidate/Bundle/Manifest 语义。

## Method Pack 安装与 Readiness

```bash
.venv/bin/python scripts/install_method_packs.py
.venv/bin/python scripts/poc_method_pack_overlay.py
```

第一条命令将锁定归档写入 `${AGENT_TEAM_OS_DATA_DIR:-.agent-team-os}/method-packs`。第二条在临时 Store
内重做 Codex Method Entry 发现和业务仓库无污染 PoC。两者都不执行 npm 安装脚本。

Method Store 缺失、哈希漂移或入口不完整时，Preview Readiness 保持 `not_ready`；Live Gate 必须是
`blocked/not_run`，不能使用复制 Prompt 回退。

## 验证层级

| 层级 | 本版本证据 | 能证明什么 |
|---|---|---|
| Unit / Contract | Python、TypeScript、OpenAPI 同步 | 领域约束和公共接口 |
| Deterministic | 四个真实本地 Bare Remote、五个 WorkcellRun、四个 Candidate/PR/Apply Receipt | 产品调度、Git 和 Forward-only 状态机；不证明模型能力 |
| BMAD/TEA PoC | 真实锁定 npm 归档、Codex 入口发现、无仓库污染 | Method Pack 安装与 Overlay 边界 |
| Live | 四个私有 GitHub 仓库、可直推 main 的服务身份、Codex 登录与持久 Method Store | 真实 Provider 与外部远端闭环 |

只有同一 Agent-Team-OS Revision 下的 Deterministic 和 Live Report 都满足
`FAIL=0` / `WARN=0` / `skipped=0` 才可以宣称版本验收。未提供 Live 仓库或凭据时，该层级是
`blocked/not_run`，不是通过。
