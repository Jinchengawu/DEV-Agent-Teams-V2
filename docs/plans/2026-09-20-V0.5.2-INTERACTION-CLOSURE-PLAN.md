## 10. 2026-09-22 Final Plan 修订：只读 Attempt transient retry

### Architecture Review recheck

- `Architecture Impact: Cross-boundary`
- `Findings`：间歇性 Provider timeout/transport/capacity 失败属于单次可观测
  `AgentAttempt` 的运行时事实，不应由重跑整个 Delivery 丢弃已完成工作；但 Writer 和
  `artifact_only` 可能产生候选区或业务工件副作用，不得原位重试。
- `Required Revisions`：旧 Snapshot 缺省 `max_transient_attempts=1`；新 built-in/pipeline
  Revision 显式冻结 `max_transient_attempts=2`、`transient_retry_backoff_seconds=1`、
  `wall_clock_budget_seconds=3600`。单次 Provider 调用 timeout 保持 `900s`。重试准入必须保证
  Workcell 剩余总预算可覆盖 `900s + cleanup reserve + backoff`，否则 fail closed。
  Main planning/synthesis 的 ordinal 使用实际最大值递增，不硬编码 synthesis 为 2。输出合同
  retry 与 transient retry 共享同一 phase 的最大 2 次 Attempt。只允许
  `workspace_access=none|candidate_read`；`workspace_write|artifact_only` 保持 fail closed。
  必须先完成取消、子进程等待与 Overlay cleanup，再创建新 Attempt。
- `ADR Required: Yes`：修订 ADR-0014，因为这改变了 Attempt 恢复与 Workcell 总预算语义。
- `Architecture Document Delta`：增加 `ARCH-20260922-01`、Attempt retry allow-list、总预算准入与
  cleanup-before-retry 不变量。
- `Outcome: Approved`。必需修订已纳入下述 Final Plan，未发现新的权威越界。

### Revised Final Plan

1. 只对 `CODEX_WORKCELL_ATTEMPT_TIMED_OUT`、`CODEX_WORKCELL_TRANSPORT_UNAVAILABLE`、
   `CODEX_WORKCELL_TRANSPORT_TIMED_OUT`、`CODEX_WORKCELL_CAPACITY_EXHAUSTED` 执行有界 transient retry。

2026-09-21 Codex exit diagnostic 的 Architecture Review 与 Reconciliation：

- `Architecture Impact: Local`。
- `Findings`：Codex CLI 非零退出的 stderr 原文属于潜在敏感瞬时数据，不能进入产品 Event、Evidence 或验收文档；若只保留 generic error code，又无法区分账户/模型访问、容量、配置、传输与协议失败。
- `Required Revisions`：仅将退出码、stderr 字节数/SHA-256、稳定错误码和 allow-list signals 作为内容寻址 Artifact 绑定到失败的可观察 `AgentAttempt`；禁止持久化 stderr 原文，失败仍由既有 Workcell terminalizer 原子终结。
- `ADR Required: no`；未改变系统权威、模块依赖、状态机、安全信任边界或 Release/Apply 语义。
- `Architecture Document Delta: none`；架构总览已经规定大日志使用内容寻址 Artifact 且 Attempt 必须可观察，无需新增架构事实。
- `Outcome: Approved`。该阶段实现后的 fresh 轨道曾将 Design Main 非零退出稳定分类为 `CODEX_WORKCELL_ACCESS_DENIED`/HTTP 401；后续 auth composition 修复已取代该历史 blocker，分类证据仍用于说明当时失败而不授权换模型或绕过冻结合同。

2026-09-21 Gate auth composition、QA Reviewer Method 与共享 Provider 容量整改的 Architecture Review 与 Reconciliation：

- `Architecture Impact: Local`。
- `Findings`：Gate app 直接构造 Method Runtime 时遗漏显式 auth reference，和 Preview composition 不一致；QA delivery 两个 Reviewer 绑定到会生成报告/质量 Gate 的完整 TEA workflow，不符合只读 review JSON 合同；每个 Workcell 各自限制并发 2 仍允许 Backend/Frontend 共四个 Reviewer 同时占用同一 Provider，真实轨道中四者全部 timeout。
- `Required Revisions`：Gate app 使用 `ContentAddressedMethodRuntime.from_environment(method_store)`，只传播 auth path/reference 且不读取或持久化 secret；QA Reviewer 改用 `bmad-code-review` 与 `bmad-review`，保留两个 review purpose；共享 `CodexWorkcellAgent` 增加容量 2 的 semaphore，排队发生在 subprocess 和 900s 单调用计时开始前。
- `ADR Required: no`；不改变系统权威、依赖方向、持久化/恢复、安全信任、Gate/Release/Apply 或 ACWM 状态语义。
- `Architecture Document Delta`：架构总览同步记录共享 Provider 容量事实与真实轨道当前状态。
- `Outcome: Approved`。auth 修正后的 fresh 轨道已证明真实 Workcell 可运行；Method 和容量整改通过聚焦回归。最新 fresh 轨道在 Design writer 超时、尚未进入 Reviewer 并发点，因此容量整改仍缺真实完整闭环证明。
